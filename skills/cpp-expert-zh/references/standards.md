# C++ 编码规则

## 命名、头文件与版本

- **CPP-STYLE-01〔默认〕** 服从 `.clang-format` 和目录约定；无约定时使用 Google 风格作为起点：类型 `PascalCase`，变量/命名空间 `snake_case`，函数 `PascalCase`，类私有数据尾随下划线，2 空格缩进。不是强制整仓转换指令。
- **CPP-STYLE-02〔必须〕** 不新增保留标识符：避免含双下划线、下划线接大写字母，避免全局作用域下划线开头。头文件宏守卫用稳定且不保留的名称；已有 `#pragma once` 或宏守卫按项目保持一致。
- **CPP-HEADER-01〔默认〕** 头文件可独立编译，直接包含所用声明的所属头，减少传递 include 依赖；不要在公共头中放 `using namespace`。模板定义、内联与全局变量遵循 ODR，避免无意的跨单元重复定义。
- **CPP-BASE-01〔必须〕** 语法与库 API 均满足最低支持工具链。`make_unique` 是 C++14，`string_view/optional/scoped_lock` 是 C++17，`span/jthread` 是 C++20，`expected` 是 C++23；编译器支持语法不代表标准库已支持该 API。

## 所有权与资源

- **CPP-OWN-01〔必须〕** 每个资源有唯一可说明的释放责任；锁、句柄、文件和事务状态优先用 RAII 管理。既有框架托管对象按其生命周期接入，不把托管裸指针再次装进拥有型智能指针。
- **CPP-OWN-02〔默认〕** 新增独立堆对象优先独占所有权；只有真实共享寿命需求才用 `shared_ptr`，注意循环引用。裸指针/引用表达借用，跨 API 转移所有权要有明确协议；不要从同一裸指针构造多个独立控制块。
- **CPP-OWN-03〔必须〕** 借用不能超过被借对象寿命；`string_view/span/iterator` 不拥有底层内存。检查临时对象、容器扩容/删除、锁释放后访问及异步回调留下的悬空引用。
- **CPP-OWN-04〔默认〕** 采用 Rule of Zero。确需自定义析构、复制或移动时，审查全部特殊成员，并按语义选择 `= default`、`= delete` 或实现；Rule of Five 不要求无条件手写五个函数。
- **CPP-OWN-05〔必须〕** 虚基类若允许通过基类指针删除，析构应为 public virtual；否则可用 protected 非虚析构禁止该用法。避免对象切片，独占资源不得被无意复制。

## 类型、接口与不变量

- **CPP-TYPE-01〔默认〕** 初始化对象与成员，优先 `nullptr`、`enum class`、有类型常量；但更换已发布枚举、宏或结构布局需先评估 API/ABI。简单可推断处用 `auto`，不能隐藏关键所有权或数值转换。
- **CPP-TYPE-02〔必须〕** 长度、索引、符号与整数溢出有边界证据；分配 `count * element_size` 之前检查乘法范围。协议宽度使用明确类型，不能把平台 `long/size_t` 当成固定网络宽度。
- **CPP-TYPE-03〔默认〕** 不需要隐式转换的单参数构造函数声明 `explicit`；确实有意的转换构造函数保留并说明。重写虚函数标记 `override`，只在设计要求禁止继承时用 `final`。
- **CPP-TYPE-04〔必须〕** 参数的借用、可空、修改和转移语义可见；小值按值，大只读对象通常 `const&`，可空借用可用指针。不要把接收智能指针当默认参数写法，只有参与所有权时才需要。
- **CPP-TYPE-05〔必须〕** 接口明确前置/后置条件；`assert` 只检查程序不变量，不能替代发行版仍需要的外部输入检查。强制转换要说明必要性，避免用 `reinterpret_cast/const_cast` 隐藏模型问题。

## 错误、异常和移动

- **CPP-ERR-01〔必须〕** 遵循现有异常/错误码/状态类型契约，尤其不能让异常穿过禁止异常的模块或 C ABI。业务失败与程序缺陷分开；不能为模仿 Google 全局禁异常，也不能向禁异常项目强加异常。
- **CPP-ERR-02〔必须〕** 有异常路径时保证不变量与资源释放，通常按 `const&` 捕获异常。析构与清理不向外抛出；可报告的关闭失败由显式操作返回，不依赖析构表达错误。
- **CPP-ERR-03〔必须〕** `noexcept` 是真实承诺，违约会终止进程。移动操作在确实不抛出时声明 `noexcept`；可能抛出的成员、分配器或操作需逐项判断，不能只为容器优化加上它。
- **CPP-MOVE-01〔必须〕** `std::move` 只是转换，不会自动转移资源，也不保证 `const` 对象被移动；移动后只按类型契约使用。返回局部值通常交给拷贝消除，不无意用 `std::move` 阻碍 NRVO。
- **CPP-ERR-04〔默认〕** 错过返回值会造成实际错误的 API，在标准支持时使用 `[[nodiscard]]`；状态码仍须处理，不能用显式丢弃消除告警而忽略失败。

## 并发与异步

- **CPP-CONC-01〔必须〕** 共享可变状态有同步与所有者；`volatile` 不是线程同步工具。atomic 只保证其规定操作，不自动维护跨字段不变量；内存序优化需可解释的正确性依据。
- **CPP-CONC-02〔默认〕** 锁用 RAII；多锁固定顺序或使用受支持的无死锁获取方式，如 C++11 `std::lock` 配合 `unique_lock`，C++17 `scoped_lock`。低层封装需手动操作时，证明所有退出路径均解锁。
- **CPP-CONC-03〔必须〕** 不在持锁时调用不受控回调或阻塞 I/O。条件变量使用谓词处理虚假唤醒；线程/任务有停止、异常处理与等待结束方案，不把 detach 当作默认生命周期管理。
- **CPP-CONC-04〔必须〕** 被存储、排队或跨线程的 lambda 捕获对象，寿命必须覆盖所有调用；优先显式捕获拥有值或受控弱引用。引用捕获只有宿主能证明生命周期时才允许；`[=]` 捕获 `this` 也不会延长对象寿命。
- **CPP-CONC-05〔必须〕** 队列、池和重试有界；取消不等于任务已退出。销毁对象前等待仍能访问它的任务结束，避免析构与回调竞态。

## 安全、兼容与性能

- **CPP-SEC-01〔必须〕** 输入长度与内存边界先校验，不使用不受控的格式串、无界字符串写入或未初始化数据；有长度限制的 C API 也要检查截断与终止符。不要把 `strncpy` 当自动安全替代品。
- **CPP-SEC-02〔必须〕** 解析二进制数据显式处理端序、对齐与对象表示，不直接把不可信字节强转成结构体指针。路径、命令、权限与随机源按安全边界处理，日志不泄漏秘密或不必要的地址信息。
- **CPP-COMPAT-01〔必须〕** 公共类布局、虚表、对齐、异常开关、编译选项和标准库 ABI 均可能影响兼容。跨动态库资源在匹配的分配/释放域释放；协议结构不直接序列化原生对象内存。
- **CPP-PERF-01〔建议〕** 先基准与 profile，再调分配、布局、拷贝或算法；优先标准容器和明确复杂度。`reserve`、池和无锁结构不因“现代 C++”自动成为必选。
