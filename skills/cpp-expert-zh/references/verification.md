# C++ 验证与审查

## 构建优先

检查构建文档、CMake/Bazel/其他实际入口、编译器和 CI 平台。复用已有 preset、toolchain、目标及测试宿主；不要另造与真实工程参数不同的编译命令作为通过依据。

| 目标 | 方式 | 限制 |
|---|---|---|
| 编译与接口 | 编译实际目标及受影响调用方，必要时独立包含公共头 | 单个文件通过不能证明链接、模板实例化或 ABI 正确 |
| 排版与静态检查 | 已安装且匹配配置的 clang-format 检查、clang-tidy/编译告警 | 不为清告警重排全仓；clang-tidy 需要真实编译参数 |
| 行为 | 项目现有 GoogleTest/Catch2/其他测试入口 | 关注不变量与错误路径，不强制更换测试框架 |
| 内存与未定义行为 | 支持时使用 ASan/UBSan 或项目等效工具 | 不同平台/编译器支持不同，记录实际范围 |
| 并发 | 支持时单独使用 TSan，配合并发场景测试 | 通常不能与 ASan 同次构建；通过不等于证明无竞争 |

## 按变更补充证据

- 所有权变化：正常销毁、提前返回、异常、移动、容器扩容、回调延迟执行。
- 解析或算术：空值、零长度、最大长度、符号转换、乘加溢出、非法编码和端序。
- 线程或锁：重复停止、取消后等待、条件变量谓词、析构期间回调、锁顺序。
- 公共 API/库：现有消费者、最低标准、目标平台构建、异常与分配边界；ABI 风险用项目已有 ABI 工具或实际消费者验证。
- 性能目标：相同构建参数下的 benchmark/profile，不能把 Debug 与 Release 对比当优化收益。

机械格式调整按范围检查即可，不要求新增行为测试。高风险资源或并发修改需要能复现对应失败路径的验证；环境不支持时明确缺口。

## 审查卡

优先 CPP-OWN 的寿命与释放、CPP-TYPE 的边界、CPP-ERR 的异常保证、CPP-CONC 的退出和同步、CPP-COMPAT 的 ABI。`#pragma once`、命名前缀等偏好单独列为可选建议，不作为内存缺陷同级问题。

报告实际目标、编译器/标准、命令、结果与未覆盖平台；没有运行 sanitizer 不能写“无内存问题”。
