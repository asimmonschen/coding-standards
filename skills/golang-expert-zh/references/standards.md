# Go 编码规则

## 风格、命名和包

- **GO-STYLE-01〔必须〕** Go 源码经目标工具链 `gofmt`；导入整理沿用现有工具。包名简短、小写且说明职责，避免 `util/common/base` 聚集无关功能。
- **GO-STYLE-02〔默认〕** 导出名 `MixedCaps`，内部名 `mixedCaps`，缩略词保持一致，如 `userID`、`HTTPClient`。文件名与目录遵循模块惯例；不把局部短变量的习惯用于跨层业务参数。
- **GO-STYLE-03〔默认〕** 导出符号说明用途、约束与所有权；注释写原因和契约。错误消息简明，不重复层层上下文；接收者名称保持一致，不使用 `this/self`。
- **GO-PKG-01〔必须〕** 包依赖方向清晰，避免循环；库代码不调用 `os.Exit/log.Fatal` 终止宿主。初始化的 I/O、后台任务和可能失败的依赖优先显式构造；合法注册型 `init` 不因风格要求被盲目移除。

## 类型、接口和数据契约

- **GO-TYPE-01〔建议〕** 接口由使用方按真实需求定义，尽量小；无替换或隔离需求时使用具体类型，不按“每个结构体一个接口”批量生成抽象。
- **GO-TYPE-02〔必须〕** 按修改意图、大小、方法集、nil 与共享语义选择指针或值；含 `sync.Mutex` 等不可复制状态的类型不按值复制，包括值接收者、返回值和容器元素复制。
- **GO-TYPE-03〔必须〕** 区分 nil 接口与包含 typed nil 的接口；错误成功路径返回字面量 `nil`。类型断言不确定时用 `value, ok`，不让外部输入触发意外 panic。
- **GO-TYPE-04〔必须〕** 明确 slice/map 的共享底层数据与并发访问责任；返回内部缓存时按契约复制或提供只读访问，不误以为复制 slice 头即可隔离底层数组。
- **GO-TYPE-05〔默认〕** 跨包结构体字面量优先字段名；零值尽可能可用。不要为“Unknown 必须等于零”改写已发布枚举值。序列化字段通过明确 tag 固定，兼容区分 nil、空集合与缺失字段。
- **GO-TYPE-06〔必须〕** 金额和 ID 避免不受控浮点转换；时间单位明确，内部优先 `time.Duration/time.Time`，序列化单位沿用协议。由接口接收的 JSON 数值需考虑默认浮点解析造成的精度丢失。

## 错误与控制流

- **GO-ERR-01〔必须〕** 检查 I/O、序列化、事务提交等错误；允许忽略的清理错误也需有明确理由。失败不能返回貌似成功的零值；error 作为多返回值最后一项。
- **GO-ERR-02〔默认〕** 需要保留错误身份时用 `%w`，判断因果用 `errors.Is/As`；是否暴露底层错误类型属于 API 决策，不盲目包装实现细节。不要匹配错误字符串分支。
- **GO-ERR-03〔必须〕** 日志在责任边界记录一次；返回错误补充可操作上下文但不包含秘密。业务可预期失败不用 panic，`recover` 仅用于明确隔离边界，不能把程序缺陷静默变成成功。
- **GO-ERR-04〔默认〕** 错误/边界早返回，减小主路径缩进；谨防 `:=` 阴影变量使外层 err 保持 nil。命名返回值仅在提高可读性时采用。

## context、并发与生命周期

- **GO-CTX-01〔默认〕** 请求上下文作为首个 `context.Context` 参数逐层传递，不传 nil，不把请求 context 长期存进服务对象。按需派生的 cancel 要执行；后台任务使用明确独立的生命周期，不能随意用 Background 丢弃调用方取消。
- **GO-CONC-01〔必须〕** 每个 goroutine 能自然结束或接收停止信号，且启动方/宿主能等待退出；不得在 `init` 偷跑无限任务。数量、队列、重试和缓存有上限，停止期间阻塞收发也要能退出。
- **GO-CONC-02〔必须〕** map 和其他共享可变状态按不变量同步；`volatile` 类思维不适用，原子字段也不自动保证多个字段一致。选 mutex/channel/atomic 以证明正确性为先，不强制依赖特定原子库。
- **GO-CONC-03〔必须〕** channel 的关闭权明确，通常由能证明全部发送已结束的一方关闭；接收方不随意关闭，防止重复 close、向已关闭通道发送及零值误读。nil channel 的阻塞特性须有意使用。
- **GO-CONC-04〔必须〕** `WaitGroup.Add` 在对应任务可能被等待前完成，旧版本通常在启动 goroutine 前调用；工作退出可靠 Done。较新辅助 API 只有在最低支持版本满足时使用。
- **GO-CONC-05〔必须〕** 锁保护范围短且明确，不在持锁期间调用未知回调或慢 I/O；多锁顺序固定。循环变量捕获按 Module 语言版本与具体赋值方式判断，不能把 Go 1.22 新语义套给旧基线或外部复用变量。
- **GO-RES-01〔必须〕** 获得资源成功后就近安排释放；循环中大量 `defer` 需评估积累，必要时提取小函数。HTTP body、文件、rows、ticker 和事务按实际版本及 API 契约关闭，检查 `rows.Err` 与关键写入的关闭/提交错误。

## 安全、存储和兼容

- **GO-SEC-01〔必须〕** 外部输入校验类型、大小、范围和资源授权；SQL 参数绑定，排序/表名用白名单；启动程序传参数数组，避免让 shell 解释用户文本。
- **GO-SEC-02〔必须〕** 路径校验考虑真实目录边界、符号链接与竞态；URL/服务端请求限制协议、目标与重定向。TLS 验证保持开启，敏感信息脱敏；安全 token 用 `crypto/rand` 而非 `math/rand`。
- **GO-DATA-01〔必须〕** 原子写入使用同一事务句柄，所有步骤及 Commit 的错误都处理；关键写操作有幂等/唯一约束及明确重试语义。进程 mutex 或临时分布式锁不能替代持久化幂等保证。
- **GO-COMPAT-01〔必须〕** Proto 字段号、JSON tag、错误码、默认值与持久化结构都是契约；字段删除按协议保留编号，生成物从源文件重建。不把某个参考仓库的路由、框架、门禁命令复制成全局规范。
- **GO-PERF-01〔建议〕** 从 benchmark/profile 确认瓶颈再预分配或引入池、unsafe、无锁结构；池对象回收前不可再被其他任务使用。不要为减少分配放大共享状态风险。
