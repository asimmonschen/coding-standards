# JavaScript 编码规范

## 使用边界

本 Skill 是按项目适配的编码规则集。只对本次任务涉及的 JavaScript 文件、接口和必要调用方应用；混合仓库按文件语言选择 Skill，不把单纯的语言名称提及当作修改代码的要求。

用户要求、目标仓库的 `AGENTS.md`、已确认的业务与协议契约先于本 Skill。保留原有正常行为；风格差异不能成为扩大重构范围的理由。对已发现的安全或正确性缺陷明确报告，不用“老代码一直这样”掩盖问题。

## 开始前确认

1. 确认任务范围、目标模块及已有验收条件；只有会改变实现方向的缺口才需澄清，不强制补建规格文档或重复申请已获授权的操作。
2. 核对浏览器/Node/嵌入式引擎版本、`package.json` 的模块类型、Babel/构建目标、包管理器及锁文件；`.jsx` 还需确认框架规则。
3. 读取格式化、静态检查、构建、测试配置及附近同类实现，确认公开接口、存储格式、错误语义、生命周期和平台约束。
4. 识别适用情形：**新项目**在无现成约定时采用本文默认值；**既有项目**跟随目标模块已验证的基线与风格。新模块也受宿主兼容约束，不因“新建文件”自动升级工具链。

## 规则力度

- **必须**：在规则所述条件成立时，保证正确性、安全、资源释放和既有契约；发现缺陷按证据修复或报告。
- **默认**：没有项目约定时的写法；既有配置或明确约定可覆盖。
- **建议**：需要结合可读性、性能证据和改动成本选择，不作为机械阻断项。

不得仅因命名、行长、函数行数、个人模式偏好，批量重排、拆类、改接口或增加依赖。不能为满足工具告警而关闭检查、吞掉异常或添加虚假类型断言。

## 核心约束

- 动态输入在边界校验；JSON 解析成功不等于业务对象有效。
- 每个异步任务有人等待或处理失败，批量并发与资源生命周期有界。
- 明确真值、数字精度、对象共享和原型风险，不依赖偶然的类型转换。
- 遵守宿主运行时和 ESM/CJS 契约，不自动改造成 TypeScript 项目。

## 按任务加载

- 编码、修改或审查前读取 [编码规则](references/standards.md)，按其中规则编号定位适用条目。
- 涉及易错写法、需要解释改法时读取 [场景示例](references/examples.md)，示例仅说明局部契约，不是整套业务模板。
- 需要执行检查或设计验证时读取 [验证与审查](references/verification.md)，使用目标项目已有入口，按改动风险选择检查。
- 需要核对来源、解释规范冲突或调整项目默认值时读取 [来源与取舍](references/sources.md)。无需每次联网或加载全部资料。

## 工作与交付

实现时先复用现有边界与工具，完成最小必要改动，并检查调用方、生成源、配置默认值及失败路径。审查时只报告可定位的问题，给出触发条件、影响和修复方向；建议与缺陷分开，不把本文所有条目逐项输出。

通常简要说明改动目的、兼容影响、已执行命令与结果。审查发现用“严重程度 / 文件与行号 / JS 规则编号 / 触发条件与影响 / 最小修复”表达。未执行、环境不支持或失败的检查如实标记；没有证据的问题写成待确认事项。

本 Skill 不自动授权发布、推送、迁移数据或修改仓库检查配置，也不要求安装特定厂商规则包。每个目录可独立分发，不依赖其他语言 Skill。
