# JavaScript 编码规则

## 命名、风格与模块

- **JS-STYLE-01〔默认〕** UTF-8，现有 formatter 优先；无约定时 2 空格、单引号、分号。ESLint 管逻辑问题，formatter 管排版，沿用已有兼容配置，不混套多个完整公司规则包。
- **JS-STYLE-02〔默认〕** 变量/函数 `camelCase`，类/构造器 `PascalCase`，布尔名称表达 `is/has/can`；固定领域常量按项目约定。文件名与大小写遵循目录规则，避免本机能导入而 Linux 失败。
- **JS-MOD-01〔默认〕** 无历史约束且运行环境支持的新项目优先标准 ESM；现有 CJS/AMD/全局脚本维持宿主契约。切换 `type`、扩展名或 exports 属于兼容改动，不随风格修复一起做。
- **JS-MOD-02〔建议〕** 模块只暴露稳定接口，避免导入即启动网络/定时器等副作用与循环依赖；需要初始化时提供明确入口。依赖通过参数或现有装配层传入，不堆全局状态。

## 值、类型与数据

- **JS-VALUE-01〔默认〕** 默认 `const`、需重新赋值才用 `let`；新代码不新增 `var`，除非目标引擎与构建约束要求。`const` 不会冻结对象内容。
- **JS-VALUE-02〔必须〕** 默认用 `===/!==`，显式转换确有语义时写清楚；`value == null` 仅在项目允许且有意同时匹配 null/undefined 时使用。不要用真值判断代替存在性判断。
- **JS-VALUE-03〔必须〕** 外部输入验证类型、结构、长度与范围；`JSON.parse` 只校验 JSON 语法。数组用 `Array.isArray`，对象需排除 null；schema/JSDoc/编辑器推断不自动提供运行时防护。
- **JS-VALUE-04〔必须〕** 区分缺失、`undefined`、`null`、空串、零与 NaN；合法零值默认使用 `??` 或兼容写法，而不是 `||`。数字转换检查 `Number.isFinite/Number.isSafeInteger` 等适用条件，不用 `parseInt` 宽松截断充当严格验证。
- **JS-VALUE-05〔必须〕** 大整数 ID 与精确金额不经过不安全的 `number` 转换；整数最小单位仍需检查范围。`BigInt` 与 number 混算、JSON 序列化需要明确适配；不能靠浮点保留两位保障账务正确。
- **JS-VALUE-06〔必须〕** 对象展开和 `Object.assign` 是浅拷贝；排序等原地方法会修改原数组。输入/缓存/共享对象的变更责任明确，不误以为复制顶层就消除嵌套共享。
- **JS-VALUE-07〔建议〕** 维护公开接口时用 JSDoc 或现有 schema 描述参数、返回和异步行为；不强制把 JS 改为 TS，也不为只读检查一次性打开全仓 `checkJs`。

## 函数与控制流

- **JS-FUNC-01〔默认〕** 提前处理边界，保持主路径平坦；数组转换用 map、筛选用 filter、普通遍历用循环或 forEach，避免依赖无返回的 map 或晦涩 reduce。
- **JS-FUNC-02〔必须〕** 箭头函数与普通函数按 `this` 语义选；不要用箭头定义需要动态接收者的方法，不随意将方法解构成丢失 `this` 的回调。外部回调遵循实际宿主签名。
- **JS-FUNC-03〔必须〕** `for...in` 可能遍历继承属性，默认对象数据遍历使用 `Object.keys/entries`；需要属性存在性时使用目标运行时支持的安全 own-property 检查，不直接信任输入对象的 `hasOwnProperty` 方法。

## 错误与异步

- **JS-ERR-01〔默认〕** 抛出 Error 或项目约定的错误类型，保留原始原因；既有公共错误码保持稳定。catch 只在恢复、转译或边界记录时使用，不将失败替换成假成功。
- **JS-ERR-02〔必须〕** 清理不覆盖主结果，不在 finally 中意外 return；库函数不随意退出整个进程。日志责任单一，对外不泄漏内部堆栈或敏感值。
- **JS-ASYNC-01〔必须〕** Promise 必须 await、return 或交给会处理失败的宿主；`void` 与全局 unhandled-rejection 监听不是逐任务错误策略。不要使用 `new Promise(async executor)`。
- **JS-ASYNC-02〔必须〕** 不能用 `forEach(async ...)` 期待完成或顺序。顺序依赖串行执行；独立任务并行时限制并发数、队列和重试。`Promise.all` 失败不会取消其他请求，`allSettled` 的失败结果也需处理。
- **JS-ASYNC-03〔必须〕** 超时应作用于实际 I/O，支持时传播取消；只有 `Promise.race` 不会停止底层任务。监听器、timer、stream、连接和订阅均有明确释放者，结束后不能继续写已销毁状态。
- **JS-ASYNC-04〔必须〕** 事件循环之间也存在异步交错；避免先读后写跨 await 导致状态丢失。请求序号、取消或幂等方案按实际业务选择，UI 防抖不能替代服务端原子性。
- **JS-PERF-01〔建议〕** 避免在敏感事件循环执行大规模同步 I/O、CPU 密集计算、巨大 JSON 或高风险正则；先测量再引入 Worker/分片，不默认新增架构。

## 安全与兼容

- **JS-SEC-01〔必须〕** 文本写入安全文本 API；需要 HTML 时经认可方案净化，不拼接用户输入执行 eval/Function/字符串定时器。服务端 SQL 参数化，命令用独立参数且避免 shell 解释。
- **JS-SEC-02〔必须〕** 来自用户的键值集合采用字段白名单、安全字典或 Map；防范 `__proto__`、`constructor` 等键进入危险深合并路径。只换一个容器不能证明所有合并链安全。
- **JS-SEC-03〔必须〕** `postMessage` 验证来源、窗口和消息结构；发送明确目标 origin。URL 和文件路径按解析后的边界验证，服务端请求考虑内网、重定向与 DNS 风险。
- **JS-SEC-04〔必须〕** 权限在可信端判断；客户端打包内容不能存秘密。日志脱敏，安全随机值使用 Web Crypto/Node crypto 或宿主安全源，不使用 `Math.random()`。
- **JS-COMPAT-01〔必须〕** 语法转译不等于运行时 API/polyfill 支持；确认 `fetch/AbortController/Object.hasOwn` 等目标环境能力。更新导出、序列化、时间格式和配置默认值时验证旧调用方。
- **JS-COMPAT-02〔必须〕** 沿用生成文件的权威源、锁文件与构建流程；不要手改构建产物修复源码问题，不因采用新的 lint 规则包擅自升级运行时。
