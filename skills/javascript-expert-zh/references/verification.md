# JavaScript 验证与审查

## 使用项目现有工具

读取 `package.json`、锁文件、CI、构建与浏览器目标。使用已安装的 ESLint/formatter 和测试脚本，不自动拉取最新版配置或工具。

| 目标 | 检查方式 | 局限 |
|---|---|---|
| 语法与逻辑 | 仓库 lint/build；Node 支持时对目标文件 `node --check path/to/file.js` | 语法通过不能证明浏览器 API、权限或业务正确 |
| 格式 | 现有 formatter 检查模式 | 不全仓自动修复 |
| 类型辅助 | 已配置的 JSDoc/checkJs 流程 | 不代替运行时输入验证，不擅自改造成 TS |
| 行为与兼容 | 目标单测、必要组件/端到端测试、实际模块入口与最低运行时 | 仅跑当前 Node 不代表旧浏览器或嵌入式引擎兼容 |

## 按风险选择场景

- 值：缺失、null、undefined、0、false、空串、NaN、过大整数和输入格式边界。
- 对象：继承键、危险键、浅拷贝共享、数组原地修改、回调 this 丢失。
- 异步：拒绝、超时/取消、乱序、重复事件、部分成功，以及结束后不再写入旧状态。
- 安全：DOM 输出、消息来源、权限和注入边界；使用隔离数据，不访问真实生产目标。
- 模块：ESM/CJS 消费入口、构建产物、路径大小写和最低运行时 API。

行为变更补充对应测试；机械排版或文案变化无需套用全部场景。测试异步优先用可控依赖与假时钟，避免靠真实睡眠赌执行顺序。

## 审查卡

优先 JS-VALUE 的转换与共享、JS-ASYNC 的任务归属与清理、JS-SEC 的可信边界、JS-COMPAT 的宿主。风格改进只在能改善当前代码且不扩大范围时提出。

交付记录实际命令、目标环境与结果；缺少浏览器或宿主集成验证时明确说明，不用 lint 结果代替行为结论。
