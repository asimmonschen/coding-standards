# Python 编码规则

## 风格、命名和导入

- **PY-STYLE-01〔默认〕** UTF-8、4 空格；函数/变量/模块 `snake_case`、类 `PascalCase`、常量 `UPPER_SNAKE_CASE`。已有 formatter 与行宽优先，无工具配置且无约定时遵循 PEP 8 的 79 字符基线；不为长字符串或 URL 机械拆行。
- **PY-STYLE-02〔默认〕** 模块/公共 API docstring 描述参数契约、返回、异常和副作用；使用项目既定的 Google/NumPy/其他文档风格，不混搭。注释解释原因，不重复类型注解。
- **PY-IMPORT-01〔默认〕** 标准库、第三方、本地导入分组；避免星号导入和循环依赖。局部导入仅在可解释的延迟、可选依赖或循环处理需求下使用，不机械全搬到文件顶层。
- **PY-IMPORT-02〔必须〕** 导入模块不无意启动 I/O、进程或无限后台任务；命令行入口使用项目入口点或 `if __name__ == '__main__'`。库函数不得随意 `sys.exit` 终止调用进程。

## 类型、值和数据模型

- **PY-TYPE-01〔默认〕** 公共接口与复杂内部边界提供有用的类型注解，简单局部值不重复标注。沿用 mypy/pyright/其他现有方案，新增类型检查分步推进，不用无依据的 Any、cast 或全文件 ignore 掩盖问题。
- **PY-TYPE-02〔必须〕** 注解、TypedDict、dataclass 与 `typing.cast` 不自动校验运行时数据。网络、JSON、配置等输入需按 schema 或显式解析验证字段、范围与资源授权；优先复用既有验证器。
- **PY-TYPE-03〔必须〕** `None` 用 `is/is not`，业务值相等用 `==`；不要用 `is` 比较字符串或整数值。区分 None、空容器、0、False，不能用 `x or default` 覆盖合法零值。
- **PY-TYPE-04〔必须〕** 不使用意外共享的可变默认参数；dataclass 容器字段使用 `default_factory`。类属性、浅拷贝和闭包的共享语义需明确，循环闭包注意晚绑定。
- **PY-TYPE-05〔必须〕** Python 中 bool 是 int 子类；严格整数领域需按契约排除布尔值。金额使用整数最小单位或项目 Decimal 方案；Decimal 从字符串/精确值构造，不能期待先经过 float 后恢复精度。
- **PY-TYPE-06〔必须〕** 文本与 bytes 的边界及编码明确；时间的时区和序列化格式明确。不要混用 naive/aware datetime，跨系统时间通常沿用带时区的既有协议。
- **PY-TYPE-07〔建议〕** 用 dataclass/简单值对象表达稳定数据，只有需要结构化行为和不变量时才建类。Protocol、继承与泛型解决真实替换需求，不为单一实现批量造抽象。

## 函数、控制流和异常

- **PY-FLOW-01〔默认〕** 简单转换用可读推导式，复杂流程显式循环；避免多层嵌套推导式、具有副作用的表达式与隐藏共享状态。按职责拆分，不按函数行数硬切。
- **PY-ERR-01〔必须〕** 捕获能处理的具体异常，缩小 try 范围；不使用空 `except` 或把任何失败变成成功。任务隔离边界可捕获 Exception，但应记录/转换并保证可观察失败，不覆盖所有 BaseException。
- **PY-ERR-02〔必须〕** 转换异常保留因果，如 `raise DomainError(...) from exc`；仅确需隐藏内部细节时按边界策略抑制展示，并保留内部诊断。错误消息与日志不包含秘密，不在每层重复告警。
- **PY-ERR-03〔必须〕** 外部输入验证使用正常控制流，不能依赖可被 `-O` 关闭的 assert。assert 用于内部不变量，不能承担权限或金额检查。
- **PY-ERR-04〔必须〕** `finally` 中不 return 或抛出无关异常覆盖主结果；清理失败按契约表达。日志用项目结构化接口或参数化日志，避免输出隐私、令牌和完整敏感负载。

## 资源、并发和异步

- **PY-RES-01〔必须〕** 文件、锁、事务、连接与临时资源优先 `with/async with` 或可靠 finally 管理；获得资源后立即建立清理责任。生成器或异步迭代提前结束时也要考虑其资源寿命。
- **PY-ASYNC-01〔必须〕** coroutine 要 await，后台 task 必须有宿主保存并观察结果；“create_task 后不管”可能丢失异常和生命周期。完成/关闭时按策略取消并等待任务，不把发出 cancel 当成任务已结束。
- **PY-ASYNC-02〔必须〕** 取消应在清理后按契约传播，不吞掉 `CancelledError`。`TaskGroup`、超时上下文与 ExceptionGroup 等特性按最低 Python 版本使用，不能把新 API 套给旧解释器。
- **PY-ASYNC-03〔必须〕** async 函数内不用同步网络/文件调用或 `time.sleep` 阻塞敏感事件循环；需要时复用异步库或受控执行器。执行器任务取消不保证工作线程里的操作停止，仍需实际 I/O 超时和收尾策略。
- **PY-CONC-01〔必须〕** 不依赖 GIL 保护跨操作不变量；共享状态由锁、消息或不可变快照同步。区分线程锁和 asyncio 锁，不持线程锁跨 await；多进程考虑序列化、启动方式和资源继承。
- **PY-CONC-02〔必须〕** 并发数、队列、缓存和重试有上限；对网络超时、部分成功、关闭以及重复执行有明确行为。对外重试仅在幂等或既有补偿条件下进行。
- **PY-PERF-01〔建议〕** 先 profile，再优化算法、批量 I/O、生成器或并发。惰性迭代不自动保证资源释放，不因“Python 慢”就改成多进程或新增缓存层。

## 安全、存储与兼容

- **PY-SEC-01〔必须〕** SQL 绑定参数，动态标识符白名单；子进程采用参数序列与默认 `shell=False`，对可执行程序、参数和平台语义仍做验证。不要把不可信输入传入 eval/exec 或格式串构造的可执行语句。
- **PY-SEC-02〔必须〕** 不反序列化不可信 pickle；YAML 等使用安全解析模式，限制输入规模和复杂度。模板遵循框架转义规则，不将“安全字符串”标记当净化工具。
- **PY-SEC-03〔必须〕** 文件路径、解压条目和服务端 URL 按真实信任边界验证，考虑符号链接、竞态、重定向与内网目标；简单 resolve/前缀判断不能解决所有竞态。临时文件用标准安全 API。
- **PY-SEC-04〔必须〕** 权限在可信边界判断，秘密从已批准的配置/密钥设施读取。安全随机用 `secrets` 或 `os.urandom`，不是 `random`；不关闭证书验证掩盖连接问题。
- **PY-DATA-01〔必须〕** 事务写入沿用同一事务句柄，失败回滚且提交失败可见；幂等需要持久化约束与明确重复结果。不能用内存锁证明跨进程唯一性。
- **PY-COMPAT-01〔必须〕** 新语法、类型表达及标准库均满足 `requires-python` 和真实依赖基线；后置注解不自动使全部新语法/API 在旧版本可用。保持公开签名、异常类型、默认参数与序列化语义。
- **PY-COMPAT-02〔必须〕** 用锁定依赖和虚拟环境执行检查，避免污染全局解释器；沿用项目打包与生成链，不手改生成文件或为小改重建整套环境。
