# Python 验证与审查

## 环境与入口

从项目文档、`pyproject.toml`、锁文件及 CI 确认解释器和运行方式。优先现有 uv/Poetry/pip/其他虚拟环境，不自动升级依赖或使用全局环境替代锁定环境。

| 目标 | 优先方式 | 备选与限制 |
|---|---|---|
| 风格与静态检查 | 项目已有 Ruff/Flake8/Pylint 等脚本 | 无现成配置的新项目可选 Ruff；不同时安装多套重叠规则 |
| 格式 | 已有 Black 或 Ruff format 等检查模式 | 两者选定一套，不对同一代码反复互相格式化 |
| 类型 | 现有 mypy/pyright 等命令 | 只证明静态假设，不替代输入验证 |
| 行为 | 项目 pytest/unittest/其他入口 | 无封装且已使用相应框架时，可用 `python -m pytest` 或 `python -m unittest` |
| 兼容 | 既有 tox/nox/CI 版本矩阵与包构建 | 当前解释器语法通过不代表最低版本、依赖和 wheel 可用 |

可用语法检查作补充，但不能代替行为测试。只为本次改动执行必要范围；安全、并发或边界行为变化增加对应回归用例。

## 风险场景

- 数据：None、零、False、空集合、bool/int 混淆、非法 JSON、金额精度和时区。
- 可变状态：重复调用、多个实例、默认列表共享、浅拷贝与闭包晚绑定。
- 异常/资源：具体异常匹配、因果保留、打开失败、提前退出、关闭/提交失败。
- 异步/线程：超时、取消后等待、任务异常、宿主关闭、并发上限；测试不靠固定睡眠碰调度。
- 安全/兼容：权限与注入边界、旧配置与 API、最低版本语法；使用隔离资源验证，不访问生产。

真实 SQL、进程与文件权限语义按风险使用组件/集成测试，Mock 不能证明底层实现符合预期。

## 审查卡

优先 PY-TYPE 的动态边界与共享、PY-ERR 的可观察失败、PY-RES/PY-ASYNC 的收尾、PY-SEC 的信任边界和 PY-COMPAT 的版本。只报告有触发条件和影响证据的问题。

交付记录环境、精确命令、范围、结果及未执行原因；工具未装或依赖不足不等于检查通过。
