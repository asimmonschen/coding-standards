# TypeScript 编码规则

## 风格与组织

- **TS-STYLE-01〔默认〕** UTF-8，按项目 formatter 统一排版；无约定时采用 2 空格、分号、单引号。引号、尾逗号与行宽只交给一套格式化配置，不混用不同公司的冲突默认值。
- **TS-STYLE-02〔默认〕** 变量/函数 `camelCase`，类型/类/接口 `PascalCase`；布尔值用 `is/has/can` 等语义；不默认给接口加 `I` 或给普通变量加类型前缀。固定领域常量按项目约定命名，局部 `const` 不必全大写。
- **TS-STYLE-03〔必须〕** 模块职责与公开面清晰；更改导出方式、文件大小写、路径别名或 package exports 前核对调用方与发布产物。类型专用导入在工具链支持时用 `import type`，但副作用导入必须显式保留。
- **TS-STYLE-04〔建议〕** 优先显式依赖与小函数；只为稳定的真实边界抽象，不给单一函数套服务定位器、泛型工厂或无用的 barrel 导出。

## 类型与接口

- **TS-TYPE-01〔默认〕** 新项目启用 `strict`；既有项目保持当前编译契约，分步清理类型债务。`noUncheckedIndexedAccess`、`exactOptionalPropertyTypes` 按影响评估启用，不为本次小改一次性修改全仓。
- **TS-TYPE-02〔必须〕** 网络、JSON、配置和第三方无类型数据视为未知输入，经过 schema、显式解析或可靠类型守卫后才能作为领域值使用。不要把 `JSON.parse()` 的结果直接断言为业务类型。
- **TS-TYPE-03〔默认〕** 未知值用 `unknown`，局部简单值靠推断；公共接口、递归函数和复杂返回值显式声明类型。不可避免的 `any`、`@ts-expect-error` 应缩到适配边界并说明原因；禁止无说明的全文件屏蔽。
- **TS-TYPE-04〔必须〕** 类型守卫验证声称成立的全部字段、范围与嵌套结构；只检查 `typeof value === 'object'` 不能证明领域类型。`as`、非空断言与双重断言不能替代证据。
- **TS-TYPE-05〔默认〕** 用可辨识联合表达互斥状态，重要状态分支做穷尽处理。`interface` 与 `type` 按表达能力选择，不强制只用其一；字面量联合、枚举按序列化及现有接口选择。
- **TS-TYPE-06〔必须〕** 区分缺失、`undefined`、`null`、空串和零；不要用真值判断拒绝合法的 `0/false/''`。索引访问验证存在性，开放字典考虑 `T | undefined` 或 `Map` 的缺失语义。
- **TS-TYPE-07〔必须〕** ID、金额和时间的表示与单位明确；超过安全整数范围的数据不得通过 `number` 中转。`bigint` 的 JSON 编码需要显式协议；金额遵循整数最小单位或项目精确数值方案。
- **TS-TYPE-08〔建议〕** 只读输入用 `readonly` 表达；知道它只提供静态约束，`Readonly<T>`、对象展开均不等于深度不可变或深拷贝。不要强行冻结由框架管理的对象。

## 控制流与错误

- **TS-FLOW-01〔默认〕** 默认 `const`，需要重新赋值才用 `let`；先处理失败和边界，再进入主路径。避免复杂三元表达式与依赖隐式转换的比较。
- **TS-ERR-01〔必须〕** 错误表示遵循模块已有契约；异常或 Result 各自一致，不为统一风格改写外部接口。捕获值按 `unknown` 收窄，保留可用原因，不将失败伪装成空列表或成功。
- **TS-ERR-02〔必须〕** 异常只在能恢复、补充上下文、释放资源或转换边界语义处捕获。日志与告警责任明确，不在每一层重复记录同一失败；对外错误去除内部路径、堆栈和秘密。
- **TS-ERR-03〔必须〕** `finally` 不返回值或抛出无关异常覆盖主结果；清理失败按项目约定报告，不能无意吞掉原始错误。

## 异步、资源与性能

- **TS-ASYNC-01〔必须〕** 每个 Promise 被等待、返回，或由明确的后台任务宿主接管并处理失败；`void promise` 只消除类型提示，不会捕获 rejection。异步回调能否被宿主等待须查明。
- **TS-ASYNC-02〔必须〕** 不用 `forEach(async ...)` 期待顺序或等待；依赖任务用顺序 `await`，独立任务可并行，但队列/并发/请求体有界。`Promise.all` 提前失败不会自动取消其余任务。
- **TS-ASYNC-03〔必须〕** 网络和后台操作有可执行的超时/取消方案；支持时传播 `AbortSignal`。仅用 `Promise.race` 超时不能证明底层工作停止；事件监听、定时器、流、连接按所有权清理。
- **TS-ASYNC-04〔必须〕** 避免异步回包覆盖新状态、重复提交与多次回调；按业务需要采用请求序号、取消、状态约束或服务端幂等，不能依赖禁用按钮保障数据唯一性。
- **TS-PERF-01〔建议〕** 性能优化先测量；CPU 重任务、同步文件操作和巨量 JSON 不放入敏感事件循环。不要为减少一层函数调用牺牲类型与错误边界。

## 安全与兼容

- **TS-SEC-01〔必须〕** 鉴权和资源授权在可信服务端完成；前端类型/开关不构成权限控制。SQL 参数绑定，进程启动传独立参数，避免拼接用户输入进入代码、命令或模板执行。
- **TS-SEC-02〔必须〕** DOM 文本使用安全文本 API；确需 HTML 时使用项目认可的净化方案。跨窗消息同时检查可信 `origin`、预期 `source` 和消息内容，发送时指定目标 origin。
- **TS-SEC-03〔必须〕** 外部字典限制字段，防范原型污染；URL/路径按解析后的协议、主机、目录边界校验，服务端请求还需考虑重定向、DNS 与内网地址。不得用子串匹配充当安全边界。
- **TS-SEC-04〔必须〕** 不硬编码或记录密钥、token 与敏感请求体；客户端包中的内容均视为可读取。密码学用途使用平台安全随机源，不能使用 `Math.random()`。
- **TS-COMPAT-01〔必须〕** 编译 target 不会自动补齐运行时 API；确认浏览器/Node/引擎支持及 polyfill 策略。类型新增不代表客户端一定发送字段；保持接口默认值和错误码语义。
- **TS-COMPAT-02〔必须〕** 生成的 `.d.ts`、协议客户端与其他生成文件从权威源更新；跨 JS/TS 边界同时验证运行时行为和声明一致性。
